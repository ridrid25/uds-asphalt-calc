# CFO Roadmap · Rid Finance

Интерактивный роадмап улучшений для Telegram-бота «CFO-агент». Инструмент планирования продукта: 19 улучшений, разложенных по категориям, приоритетам и трудозатратам, с психологическим обоснованием и технической заметкой к каждому.

---

## Что делает продукт

Это не трекер задач и не замена Jira. Задача одна: **помочь решить, что делать следующим** — и не потерять контекст, почему это вообще в списке.

Каждое улучшение отвечает на четыре вопроса:

| Блок | Отвечает на вопрос |
|------|--------------------|
| **Проблема сейчас** | Что именно болит у клиента сегодня |
| **Решение** | Что конкретно построить |
| **Психологический механизм** | Почему это сработает на поведение пользователя |
| **Техническая заметка** | Где в коде это живёт и чем реализуется |

Поверх этого — два способа смотреть на список: **карточки** (читать) и **матрица импакт × усилие** (решать). Плюс автоматический блок Quick wins: то, что даёт много при малых затратах.

## Как пользоваться

### Два вида

Переключатель в правой части панели управления:

- **▦ Карточки** — основной режим чтения. Каждая карточка показывает категорию, трудозатраты, шкалу импакта, проблему и краткий психологический механизм.
- **⊞ Матрица** — сетка «импакт × усилие». Строки — импакт от 10 до 6, колонки — XS / S / M / L. **Верхний левый угол = делать первым.**

### Фильтры и поиск

- **Категории** — Автоматизация, Психология, Удобство, Рост. Повторный клик по активной категории сбрасывает фильтр.
- **Приоритеты** — Критично / Высокий / Средний. Работает вместе с фильтром категорий (логическое И).
- **Поиск** — ищет по названию, тексту решения и тегам. Клик по тегу `#retention` на карточке подставляет его в поиск.
- **Сортировка** — по импакту (убывание), по усилию (от XS к L) или по приоритету.

Фильтры действуют в обоих видах: матрица показывает только то, что прошло фильтр.

### Детальная панель

Клик по карточке (или по элементу в матрице) раскрывает панель со всеми четырьмя блоками целиком. Страница автоматически прокручивается к ней. Закрыть — кнопкой ✕ или повторным кликом по той же карточке.

### Отметки о выполнении

Чекбокс в правом верхнем углу карточки или кнопка «Отметить выполненным» в детальной панели. Выполненные элементы гаснут и зачёркиваются, прогресс отражается в шапке и в плитках по категориям.

**Прогресс сохраняется в `localStorage`** под ключом `cfo-roadmap-done` и переживает перезагрузку страницы. Хранение локальное, на устройство и браузер — синхронизации между людьми нет. Сбросить прогресс: очистить этот ключ в DevTools → Application → Local Storage.

### Quick wins

Блок внизу страницы заполняется автоматически по правилу: **усилие XS или S И импакт ≥ 8**. Ничего настраивать не нужно — измените данные, и состав блока пересчитается сам.

На текущих данных под правило попадают 5 улучшений, все с усилием S: оба XS-элемента (импакт 7 и 6) до порога не дотягивают, так что ветка `XS` в правиле пока не выбирает ничего.

## Как настроить

Все данные лежат в одном файле — `src/App.jsx`, в верхней его части. Правки в четырёх константах.

### Добавить или изменить улучшение

Массив `IMPROVEMENTS`. Один элемент:

```jsx
{
  id: "healthscore",              // уникальный, латиницей — ключ React и localStorage
  category: "automation",         // ключ из CATEGORIES
  priority: "critical",           // ключ из PRIORITIES
  effort: "M",                    // ключ из EFFORTS
  impact: 10,                     // число от 6 до 10 (см. ограничение ниже)
  title: "Финансовый Health Score (0–100)",
  problem: "Клиент видит цифры, но не понимает — хорошо это или плохо.",
  solution: "Единый балл здоровья бизнеса по 6 метрикам с весами.",
  psych: "Геймификация — собственник проверяет счёт как шаги в трекере",
  techNote: "score = weighted_avg(...). Хранить в БД ежедневно.",
  tags: ["analytics", "gamification", "retention"],
}
```

Счётчик в заголовке («19 улучшений для продукта») считается из длины массива — руками ничего править не нужно.

### Правила, которые нельзя нарушать

Приложение обращается к справочникам напрямую, без запасного значения. Отсюда три жёстких требования:

1. **`category`, `priority`, `effort` должны существовать** в `CATEGORIES`, `PRIORITIES`, `EFFORTS` соответственно. Несуществующий ключ уронит рендер, а не проигнорируется.
2. **`impact` должен быть в диапазоне 6–10.** Строки матрицы заданы списком `[10,9,8,7,6]` — элемент с импактом 5 отрисуется в карточках, но в матрице просто исчезнет. Нужен другой диапазон — найдите этот список в разметке матрицы и правьте его.
3. **`id` уникален.** По нему хранится отметка о выполнении; дубль приведёт к тому, что две записи будут гаснуть вместе.

### Категории

```jsx
const CATEGORIES = {
  automation: { label: "Автоматизация", color: "#85C88A", icon: "⚡" },
  // ...
};
```

Добавление ключа автоматически даёт новый чип фильтра, новую плитку статистики и цвет левой границы карточек. Цвет используется и с альфа-суффиксами (`+"88"`, `+"22"`, `+"18"`) — задавайте его 6-значным hex, иначе прозрачность сломается.

### Трудозатраты и приоритеты

```jsx
const EFFORTS = {
  XS: { label: "XS · 1–2ч", color: "#85C88A" },
  // ...
};

const PRIORITIES = {
  critical: { label: "🔴 Критично", color: "#F06B6B" },
  // ...
};
```

Обе константы участвуют в сортировке, и порядок там **продублирован строками в коде**:

- порядок усилий — `effortOrder = ["XS","S","M","L"]` и колонки матрицы;
- порядок приоритетов — `["critical","high","medium"]` в функции сортировки (ищите `sortBy === "priority"`).

Добавляете новый уровень — обновите и справочник, и соответствующий список, иначе новый элемент уедет в конец сортировки (`indexOf` вернёт −1).

### Изменить правило Quick wins

Одна строка — фильтр в блоке Quick wins:

```jsx
.filter(i => (i.effort === "XS" || i.effort === "S") && i.impact >= 8)
```

### Внешний вид

Стили заданы инлайн, без CSS-фреймворка. Основное:

| Что | Значение | Где |
|-----|----------|-----|
| Фон | `#070709` | корневой `div` в `App` |
| Основной текст | `#D8D0C0` | там же |
| Акцент (золото) | `#C8A96E` | шапка, прогресс, активные состояния |
| Шрифт | Palatino Linotype / Book Antiqua | `fontFamily` корневого `div` |
| Пороги цвета шкалы импакта | ≥9 красный, ≥7 оранжевый, иначе золото | шкала «Импакт» на карточке |

## Деплой

Продукт статический — подойдёт любой хостинг статики.

```bash
npm run build        # результат в dist/
```

Содержимое `dist/` заливается на GitHub Pages, Netlify, Vercel, S3 или в любой nginx. Бэкенд, переменные окружения и секреты не требуются.

Если приложение живёт не в корне домена, задайте базовый путь в `vite.config.js`:

```js
export default defineConfig({
  plugins: [react()],
  base: '/cfo-roadmap/',
})
```
